第一章 · DWS 基础

DWS 是什么？

DingTalk Workspace CLI

DWS 是面向钉钉工作台能力的命令行工具，负责认证、群聊、联系人、机器人和事件流操作。

本项目中的位置

DWS 不执行 AI，它负责把群消息送进 Worker，并提供群、成员、机器人等管理能力。

理解 DWS 的关键：它是消息与钉钉资源的控制入口，不是模型执行引擎。
第一章 · DWS 命令

认证与事件：dws auth / dws event

dws auth status dws auth login --device dws event +listen-im \ --kind all-group --events message \ --format ndjson

auth

查看登录状态、企业、账号和 Token 有效期；Device Flow 可在其他设备完成授权。

event

订阅群消息事件。每行输出一条 NDJSON，group-worker 持续读取。

第一章 · DWS 命令

群聊与联系人：dws chat / dws contact

dws chat +chat-search --query "群名称" dws chat +chat-members-list --conversation-id <groupId> dws chat +chat-bots --group <groupId> dws contact +search-user --query "姓名" dws contact +me

这些命令支撑群搜索、成员选择、机器人校验、授权人员识别和历史消息补偿。

第一章 · DWS 命令

消息发送与机器人管理

dws chat message send \ --conversation-id <openConversationId> \ --text "消息内容" --yes dws chat +chat-add-bot \ --robot-code <Client ID> \ --id <openConversationId> --yes
注意：发送和加群都使用当前事件中的 openConversationId，不能用群名称替代。

第二章 · Agent 抽象

业务层只认识一个入口

runAgent(agent, prompt, sessionId, config, callbacks) agent === "pi" → runPi(...) agent === "codex" → runCodex(...)

统一输入

Prompt、Session ID、工作目录、模型和事件回调。

统一输出

AgentResult：sessionId、text、toolStats、durationMs。

思考题

为什么不在 group-worker 里直接 spawn Pi 或 Codex？

答案：隔离协议差异，后续替换 Agent 不需要改消息业务。
第二章 · Pi

Pi：RPC 长连接

spawn pi--mode rpc
→
get_state拿 sessionId
→
promptJSON stdin
→
JSONL 事件delta / tool / settled

实时能力

text_delta 持续更新卡片；tool_execution_start 展示工具调用。

运行中引导

新消息可以转换为 steer 指令，直接写入正在运行的 Pi 进程。

Pi 的核心关键词：RPC、持续进程、增量事件、steer。
第二章 · Codex

Codex：Exec 单轮进程

codex exec --json --skip-git-repo-check \\ --dangerously-bypass-approvals-and-sandbox \\ --cd <workDir> - stdin → Prompt stdout → thread / tool / message / turn.completed

新会话

使用 codex exec，并通过 --cd 指定工作目录。

恢复会话

使用 codex exec resume <sessionId>，继续原有上下文。

Codex 当前轮结束后进程退出；后续消息由本地队列合并为下一轮任务。

第六章 · 稳定性

为什么不会无限循环？

01

身份过滤

识别机器人 ID、名称、bot 元数据和 DWS 发送标记。

02

事件去重

使用 message_id、event_id 或 sender + 时间 + 内容构造 eventKey。

03

状态持久化

保存卡片、Session、回复历史和历史轮询游标。

工程化的核心不是“让 Agent 能跑”，而是让消息只被正确处理一次。
随堂练习

请你判断：这条消息会不会触发 Agent？

场景：群 G1 中用户 U1 发送了一条消息；机器人已经在群；但是配置 targets 中只有 G1 + U2。

问题：这条消息会进入 GroupQueue 吗？

不会。acceptsTarget 要求 groupId + senderId 同时匹配，G1 + U1 不命中。

场景：用户执行“打开 AI”，机器人不在群，但 Dashboard 未配置 Client ID。

问题：系统会怎样？

不会自动加群，会发送失败提示，要求先配置 Client ID 或手动加群。
课程小结

记住这六句话

1. 钉钉和 DWS 是两个消息入口。
2. Worker 负责秩序，Agent CLI 负责执行。
3. Pi 是 RPC，Codex 是 Exec + JSONL。
4. Agent 切换受 Dashboard 和当前会话状态影响。
5. 群聊权限的最小单元是 groupId + senderId。
6. “打开 AI”会检查机器人，必要时自动加群并写入规则。
